1. Introdução

Este projeto apresenta a modelagem e implementação de um banco de dados relacional utilizando SQLite, com o objetivo de organizar informações de equipamentos, técnicos, solicitantes e medições de calibração da Schulz S.A.

A proposta busca substituir o armazenamento baseado exclusivamente em planilhas por uma estrutura relacional, facilitando consultas e reduzindo a repetição de dados.

2. Estrutura do Banco de Dados

O banco foi organizado em três tabelas principais.

TabelaFinalidade
tecnicos Armazena a identificação dos técnicos e solicitantes.
equipamentos Armazena o cadastro dos equipamentos calibrados.
medicoes Armazena os resultados e informações de calibração.

3. Relacionamentos

As tabelas possuem chaves primárias (PK) para identificar cada registro e chaves estrangeiras (FK) para estabelecer os relacionamentos entre elas.

A tabela de medições referencia o equipamento, o técnico executante e o solicitante da calibração. Isso permite registrar diversas medições para um mesmo equipamento sem repetir todos os dados cadastrais.

4. Dicionário de Dados

O dicionário documenta 25 campos distribuídos nas três tabelas. Foram utilizados os tipos INTEGER, TEXT e REAL, de acordo com as necessidades de armazenamento.

Entre os campos estão código, denominação, parâmetro avaliado, valor nominal, tolerâncias, medidas realizadas, média, desvio padrão, valor obtido, erro e status.

5. Implementação SQLite

O banco foi implementado por meio do arquivo 03_banco.sql, contendo os comandos CREATE TABLE, PRIMARY KEY, FOREIGN KEY e restrições de integridade.

O arquivo gerado recebeu o nome schulz_calibracao.db.

6. Testes Realizados

Foram realizados testes de criação das três tabelas, cadastro de técnico, cadastro de equipamento e registro de medição.

Também foi realizado um teste de chave estrangeira, no qual o banco impediu a inclusão de uma medição associada a um equipamento inexistente.

A verificação PRAGMA integrity_check retornou o resultado "ok".

Uma consulta utilizando JOIN permitiu recuperar informações do equipamento, técnico, solicitante e medição em um único resultado.

8. Conclusão

A implementação do banco SQLite demonstrou como organizar informações de calibração utilizando tabelas relacionadas, chaves primárias e estrangeiras.

Os testes confirmaram o funcionamento da estrutura proposta e sua capacidade de armazenar e consultar dados de equipamentos e medições.

O projeto representa uma estrutura inicial para a organização dos registros de calibração, podendo ser ampliado em etapas futuras.
